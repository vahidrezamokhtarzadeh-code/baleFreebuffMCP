# 📋 Implementation Plan — Token Auth & Inline Keyboard Menu

## Overview

Add two features to Bale Freebuff Bot:
1. **Inline keyboard buttons** for Session Status and Help menus
2. **Token-based authentication system** — each Bale user gets a unique token, must authenticate with `/start <token>` before using the bot. Each authenticated user gets their own Freebuff session.

## Architecture Change

```
BEFORE:  chatId → session    (1 chat = 1 session)
AFTER:   userId → token + session    (1 user = 1 auth + 1 session)
```

---

## Feature 1: Inline Keyboard Menu

### Bale API Support

Bale's Bot API is Telegram-compatible. `sendMessage` accepts a `reply_markup` parameter:

```json
{
  "reply_markup": {
    "inline_keyboard": [
      [
        { "text": "📊 Session Status", "callback_data": "status" },
        { "text": "📖 Help", "callback_data": "help" }
      ]
    ]
  }
}
```

### Changes to `src/bale.js`

Add new method:

```js
async sendInlineKeyboard(chatId, text, keyboard, opts = {})
```

- `keyboard` is a 2D array of `{ text, callback_data }` buttons
- Sends via `sendMessage` with `reply_markup.inline_keyboard`

### Changes to `src/bridge.js`

- After successful `/start <token>` authentication → show inline keyboard
- Handle `callback_query` updates:
  - `callback_data: "status"` → show session status
  - `callback_data: "help"` → show help text
  - Answer the callback query to remove loading spinner

### Changes to `src/index.js`

- In the polling loop, also handle `update.callback_query` (not just `update.message`)
- Forward callback queries to `bridge.handleCallbackQuery(query)`

## Feature 2: Token-Based Authentication

### Token Format

- **Random 8-character alphanumeric** string (e.g., `a7x9k2m1`)
- Generated by `crypto.randomBytes` or similar

### Storage: `src/user-store.js`

**File:** `users.json` (created on first use, appended to `.gitignore`)

**Schema:**

```json
{
  "123456789": {
    "token": "a7x9k2m1",
    "username": "ali_dev",
    "firstName": "Ali",
    "authenticated": false,
    "createdAt": "2026-08-19T12:00:00.000Z"
  }
}
```

**`UserStore` class methods:**

| Method | Description |
|--------|-------------|
| `constructor(filePath)` | Load users.json (or create empty) |
| `registerUser(userId, username, firstName)` | Save user if new, generate 8-char token, return token. If user exists, return existing token. |
| `authenticateByToken(token)` | Find user by token, set `authenticated: true`, return `{userId, success}` |
| `isAuthenticated(userId)` | Return `true` if user exists and `authenticated === true` |
| `getToken(userId)` | Return user's token (or null) |
| `getUser(userId)` | Return full user record |
| `_save()` | Write users.json to disk |
| `_generateToken()` | Static: random 8-char alphanumeric |

### Flow: `/start` (no token)

```
User sends /start
  │
  ├─ New user (not in users.json)
  │   → registerUser(userId, username, firstName)
  │   → Send: "🔑 Your token: a7x9k2m1\n\nUse /start a7x9k2m1 to activate"
  │
  ├─ Existing user, NOT authenticated
  │   → Send: "🔑 Your token: a7x9k2m1\n\nUse /start a7x9k2m1 to activate"
  │
  └─ Already authenticated
      → Show main menu with inline keyboard buttons
```

### Flow: `/start <token>`

```
User sends /start a7x9k2m1
  │
  ├─ Token invalid (not found)
  │   → Send: "❌ Token is not valid."
  │
  ├─ Token belongs to another user
  │   → Send: "❌ This token belongs to another user."
  │
  └─ Token matches this user
      → authenticateByToken(token) → authenticated = true
      → Send: "✅ Authenticated!\n\n🤖 Welcome to Freebuff Bot!"
      → Show inline keyboard: [📊 Session Status] [📖 Help]
```

### Flow: Authenticated user sends text

```
User sends "write a hello world script"
  │
  ├─ isAuthenticated(userId) → false
  │   → Send: "⛔ You need to authenticate first.\nUse /start <your_token>"
  │
  └─ isAuthenticated(userId) → true
      → Session keyed by userId (not chatId)
      → Freebuff session created/used for this user
      → Response sent back
```

### Flow: Callback query (inline button press)

```
User taps "📊 Session Status"
  │
  ├─ Not authenticated → Send: "⛔ Authenticate first"
  │
  └─ Authenticated
      → Answer callback query
      → Check session by userId
      → Send status message
```

## Session Keying Change

**Before:**
```js
this.sessions = new Map(); // chatId → FreebuffSession
```

**After:**
```js
this.sessions = new Map(); // userId → FreebuffSession
```

This means:
- Each Bale user gets exactly one Freebuff PTY process
- If the user chats from different chats (group + DM), they share the same session
- Session lifecycle tied to user identity, not conversation

## Edge Cases

1. **User sends `/start` again after auth** → Show main menu with buttons (idempotent)
2. **User sends `/start <token>` with already-used token** → "Token already used by another user"
3. **User sends `/start <wrong_token>`** → "Token is not valid"
4. **Multiple users try to use same token** → Second user gets "This token belongs to another user"
5. **users.json corrupted** → UserStore falls back to empty state, new tokens generated
6. **User not authenticated but sends text** → Blocked with auth reminder
